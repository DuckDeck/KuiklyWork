## 已实现

- Android / iOS 原生进程级串行任务；返回详情外的应用页面仍可下载。同一时刻只允许一组，不自动排队。
- 列表右下角圆环显示已保存张数的整数百分比，点击返回对应组；中断显示“已暂停”，全部完成隐藏。
- 2026-10-29 布局调整：圆环放大至 80；百分比与“张数/总数”在圆内上下居中排列，暂停时也保留两行数字，暂停提示在圆外下方。
- 每张保存后同步记录进度；启动应用只恢复状态，不启动网络下载。再次点击该组“继续下载”恢复原始清单，跳过已发布文件，未完成的单张从头下载。
- 详情分页清单完整且可识别后才允许新建任务；HTTP 200 的登录页或维护页不算成功解析。
- 图片保留原始格式。Android 沿用媒体/外部文件保存位置；iOS 保存到 Documents，不导入相册。
- 不增加系统后台下载服务、通知、权限、自动重试队列或单张字节续传。

## 独立复核后的修正

1. Android 在联网前识别 MediaStore 的 `IS_PENDING=0` 且有有效内容的记录，以及已原子发布的旧系统文件；发布成功但日志未写入时不重新打开、截断该图片。
2. 两端按目标 URL 选 Cookie，并在每次重定向重新选择；不把 nncos.com 的凭据发往 nncos.us。超出支持图片源的重定向拒绝下载。
3. Android 新的“重新下载”任务首次保存失败，保留旧 completed 记录，不误变为续传旧任务。
4. Android 成功/中断状态与活动执行占用在同一锁内释放，移除旧执行 finally 二次释放导致的同组恢复竞态。
5. 以持久化任务状态过滤完成记录：主记录成功而恢复副本或最终任务保存失败时，不提前出现新的“已下载”；保留真正历史完成过的标记。
6. 未识别的详情分页使整份清单不可提交，同时保留已加载预览供浏览。
7. 共享 XCTest scheme 原被忽略，已增加仅针对该 scheme 的例外。

## 实现裁定与兼容性

- 按用户选择使用当前目录新分支，不迁移工作区、不覆盖原分页改动。
- 圆环接收响应式快照 getter，使 Canvas 和文字随每次原生快照更新，避免捕获初始状态。
- 完成记录继续使用现有存储；任务内部增加 previouslyDownloaded 作跨文件收尾的可见性屏障，不存登录凭据。该字段默认 false，旧任务文件仍可读。
- 不保证后台/锁屏连续运行，不恢复卸载后未完成的任务，不校验用户事后删除或外部修改过的文件；沿用当前 VIP 可访问内容策略，不绕过权限。
