# 单组图片独立下载与中断续传

## 已确认的用户体验

- 支持 Android、iOS，暂不处理鸿蒙。
- 下载不依赖图片详情页；应用内返回列表、切换图片组后，正在执行的任务继续。
- 同时只执行一个图片组，不建立自动下载队列。正在下载 A 时，启动 B 返回“已有一组图片正在下载”，不替换 A。
- 返回列表后，在右下角显示圆形下载进度，中央显示整数百分比；点击可回到对应图片组。
- 每保存成功一张图片，就持久化该图片的完成状态及保存位置。
- 强退后保留进度，但再次启动应用不自动下载。重新点击该组“下载”才继续，已保存图片不重复保存，未完成的单张重新下载。
- 网络失败、权限不足或保存失败时暂停并保留完成记录；明确展示失败原因，不能标记整组已下载。
- 全组成功后沿用已有下载记录机制，更新“已下载”标记，隐藏进度圆环。
- 不承诺切换其他应用、锁屏或进程被系统终止时继续工作；不引入系统后台下载服务或通知。

## 方案与边界

采用平台原生、进程级任务管理器：Android 单例和 iOS 单例分别管理下载生命周期、串行执行、进度持久化。共享 Kuikly 页面只提交清单、读取快照和展示状态，不保存能够驱动下载的页面回调。

不采用仅提升到共享页面单例的方案：当前各页面拥有自己的渲染上下文，关闭页面后的桥接回调不能作为任务继续的保证。不采用系统后台下载：用户明确不需要，避免增加服务、通知和平台后台约束。

圆环按“已成功保存张数 / 本次任务总张数”计算，而非下载字节数。已中断任务手动续传；不同组的中断记录可以保留，但任一时刻仅一组处于运行状态，无自动排队。

本次只改 Cos 图片组下载；彼岸单图下载保持兼容。图片保存目标沿用现状：Android 使用现有媒体保存位置，iOS 使用当前 Documents 文件保存方式，不顺带改造为 iOS 相册导入。

## 数据与桥接约定

任务清单在开始时固定，来源于当前组成功解析、去重后的可下载图片。必须等待详情分页解析完成，禁止下载过程中直接遍历会变化的页面 imageUrls。

请求清单：`detailUrl: String`、`title: String`、`imageUrls: Array<String>`、`referer: String`。

快照字段：`taskId: String`、`detailUrl: String`、`title: String`、`status: String`、`completed: Int`、`total: Int`、`message: String`。

- `status` 取 `idle | running | interrupted | completed`；无任务返回 idle、计数为 0。
- 读取已持久化的 running 任务，但本进程不存在运行执行器时，转换为 interrupted，不自动启动。
- 公共桥接方法：`startCosDownloadTask`、`getCosDownloadTask`。查询可传 detailUrl 查本组；不传时优先返回运行中的任务，否则返回最近中断任务。
- 开始本组时，若存在本组中断清单，恢复原清单，不用新解析顺序覆盖已完成下标；同组正在运行时返回现有任务，不重复执行。
- 已完成组显式点击“重新下载”时创建新 taskId，允许用户主动重新保存；该行为与续传区别清楚。
- 每张图片记录稳定的保存目标和完成状态；任务 JSON 不保存 Cookie 或其他登录凭据，网络请求使用应用当前的登录状态。
- Cookie 按实际图片 URL 的域名与路径选择，重定向后重新选择；历史 nncos.us 图片不得收到 www.nncos.com 的登录 Cookie。
- 任务内部持久化 previouslyDownloaded（开始本次任务前是否已有完成记录），不加入公共快照。完成收尾未成功时屏蔽新产生的已下载标记，但不撤销用户此前完整下载过该组的标记。
- 各组中断记录分别保存，开始其他组不能覆盖旧进度；本次不承诺卸载重装后恢复未完成任务。已有登录、下载完成记录的独立保存方式不变。

## 可靠性约束

1. 原生串行队列 / 锁保护“检查当前任务、创建任务、开始执行”，避免多页面同时点击造成并行下载。
2. 任务先持久化，才启动第一张；每张真正保存成功且进度持久化成功后，才下载下一张。
3. 文件写入与任务 JSON 分开，使用原子文件写入或同步提交；不能只依赖异步 SharedPreferences.apply / NSUserDefaults 延迟写入保证强退恢复。
4. 保存目标包含 taskId 与稳定图片序号。记录已分配的目标，强退落在“文件已保存、完成记录尚未写入”的窗口时，恢复到相同目标，避免产生重复图片。
5. Android MediaStore 新条目先记录 URI，再写内容；中断时重用本任务的未完成条目。恢复时区分写入中与已完成发布，不能把部分文件计入 completed。Android 旧版本文件、iOS 文件使用稳定路径与原子完成发布。
6. 只有全部图片成功且最终下载记录写入成功才 completed；最终记录写入失败时允许只重试收尾，不重新下载全部图片。
7. 页面关闭仅停止页面查询，不取消原生任务、不持有已销毁页面。新页面重新查询后恢复进度显示。
8. 详情分页加载失败时，不把不完整的清单提交为整组任务；沿用当前登录和 VIP 访问规则，不绕过网站权限。

## 展示细节（实现方默认）

- 圆环直径 80、描边 4，右侧及底部留出安全区域；圆内上方显示百分比，下方显示“已保存张数/总数”，已中断时仍保留这两行，圆外下方提示“已暂停”。完成或无任务时隐藏。（2026-10-29 用户要求放大圆环并将张数移入圆内。）
- 详情页继续显示下载状态，右上角根据当前组显示“下载 / 下载中 / 继续下载 / 重新下载”；同一个任务的不同页面计数一致。
- 前台页面每 500ms 查询一次；页面消失 / 销毁后停止查询，出现时立即查询。查询失败不覆盖已知任务为“完成”。
- 不增加通知、队列、自动网络恢复、单张字节续传、拖动悬浮球等未要求功能。

## 验收

- 启动 33 张的一组，返回列表后仍持续保存，圆环进度与已保存张数一致。
- A 下载中在另一组点击下载，仍只有 A 在执行，B 收到明确提示。
- 保存 10/33 后强退，重开不自动下载；点击本组下载后，只保存剩余 23 张，最终计数为 33/33。
- 网络失败时仍保留已完成张数，再次下载不重复保存已完成图片。
- 已完成组重新下载会创建新任务；此前列表翻页、VIP 预览、图片 loading 和下载记录功能不回退。
